# Standard Android Emulator host loopback is rejected for music-to-microphone routing

The Play Store ARM64 AVD remains useful for manual application installation and Appium UI automation, but it is not an audio-routing backend. A standard Android `AudioRecord` verifier produced an all-zero capture both with host audio disabled and with Emulator host audio enabled while macOS temporarily selected a Loopback virtual input; the Ranchu audio HAL logged repeated input I/O errors and silence insertion. This route also requires the macOS default input device, which violates the requirement to preserve normal desktop microphone use. Future audio-routing work therefore targets a Linux backend where PipeWire can own a dedicated virtual source and Android has direct, controllable audio-device access; it must pass the same retained positive and negative-control evidence gate before adoption.
