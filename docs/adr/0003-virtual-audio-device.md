# Waydroid PipeWire loopback is the supported music-to-microphone backend

The standard Android Emulator remains useful for manual application installation and Appium UI automation, but it is not an audio-routing backend. A standard Android `AudioRecord` verifier produced an all-zero capture both with host audio disabled and with Emulator host audio enabled while macOS temporarily selected a Loopback virtual input; the Ranchu audio HAL logged repeated input I/O errors and silence insertion. This route also requires the macOS default input device, which violates the requirement to preserve normal desktop microphone use. OrbStack was rejected because its Linux machine lacked binderfs, `/dev/dri`, and a usable desktop session for Waydroid.

The supported backend is Waydroid on Ubuntu with PipeWire PulseAudio compatibility. It owns a temporary `ushareiplay_music_sink`, sends Android playback to that sink, and selects its monitor as Android microphone input. A direct Android `AudioTrack` to Android `AudioRecord` run passed with no host playback process: peak amplitude `0.5498`, five active source-fingerprint frames, and `0.0037%` tone-ratio error. The disabled-route control had peak amplitude `0.0130` and zero active frames. Raw PCM, hashes, PipeWire stream snapshots, and a JSON result are retained at `~/ushareiplay-evidence/waydroid-acceptance-20260728` on the verified Ubuntu host. Stopping the route unloads the owned sink and restores the preceding PipeWire defaults.

The recommended host is an ARM64 Ubuntu 24.04 VM in Parallels on Apple silicon. It avoids the x86_64 host's ARM translation overhead and provides binder, GPU, and audio devices. The Parallels VM has passed native image and application startup checks; its final verifier evidence must be captured separately before release.
